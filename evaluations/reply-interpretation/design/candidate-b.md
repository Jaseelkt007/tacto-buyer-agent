# Candidate B: code-defined interpretation choices

## Usage (caller first)

```python
# Optional test wiring. Default is None and remains byte-for-byte baseline behavior.
buyer.reply_reader = ReplyReader(mode="shadow", decision_client=client)

# Inside Negotiator.observe(), before react(); one supplier's public prefix only.
reading = self.reply_reader.read(self.case, side.sid, events) if self.reply_reader else None
self.react(side, events, reading=reading)

# Offline replay uses exactly the same API; model response can be injected for fixtures.
reading = ReplyReader(mode="shadow", decision_client=fixture).read(case, sid, prefix)
```

`ReplyReader.read()` owns prompt construction, bounded calls, reference validation, audit output and duplicate suppression. It returns an immutable `ReplyReading`, never a dictionary of mutations. The policy remains the sole writer of `Side` state. A replay tool serializes the return value as reviewable JSON.

## Problem

Today `observe()` parses phrase signals then `react()` adopts a clause and compares alternate quotations. The clause-adopted guard skips differently structured alternatives even when currently offered. The existing reviewer runs after decisions, and `feedback.with_feedback()` requires a proposed move. Reusing that API before policy would create a temporal dependency. Instead, use the same underlying public messages directly; do not fabricate a draft just to satisfy the reviewer.

## Shape

The model selects among code-enumerated statements instead of generating arbitrary JSON values. This fits the existing Decisions API and limits the first experiment to one supported interpretation per reply.

The input contains `case_id`, `supplier_id`, `prefix_sha256`, current reply reference, all public messages from that supplier prefix, immutable quoted package catalog, and candidate interpretations. Message bodies are data, never instructions. Prior buyer offers provide negotiation feedback; repeated quotes do not establish requirements. Inputs contain no current proposed move, future outcome, hidden supplier profile, or other case.

Code enumerates current quoted packages and their non-price fields. Candidate kinds:

- `LINKED_CONDITION`: a particular quoted field value is explicitly required for this package's price.
- `PREFERENCE`: supplier prefers that field value but does not require it.
- `ALTERNATIVE`: the supplier explicitly presents this whole currently quoted package as another option.
- `UNCLEAR`: no supported interpretation to expose.

The first call chooses a candidate identifier or `NONE`. The second selects an exact supplier text span from a code-built source catalog or `NONE`, asking independently whether that span supports the specified interpretation. Each span has source message ID and character offsets. This produces JSON such as:

```json
{
  "schema_version": 1,
  "case_id": "case:example",
  "supplier_id": "sup:example",
  "as_of": {"message_id": "m4", "prefix_sha256": "..."},
  "status": "supported_interpretation",
  "observation": {
    "kind": "LINKED_CONDITION",
    "package": {"message_id": "m4", "term_sheet_id": "B"},
    "field": "contract_months",
    "value": 36,
    "evidence": {"message_id": "m4", "start": 18, "end": 68,
                 "quote": "This price requires a three-year agreement."}
  },
  "policy_effect": "advisory",
  "validation": {"references": "valid", "semantic_truth": "not_proven"}
}
```

Offsets above are illustrative. `value` and quotation text are copied by code from the selected field/span, never generated by the model. `NONE`, provider failure, incomplete context, stale input and conflicting interpretations have separate statuses, not a common "no issue" result.

`ScopedObservation` is a discriminated union: alternative has package/evidence; preference or condition also has a field whose value resolves from that package. No free-form constraints, economic estimates, actions or arbitrary JSON patches are exposed. This concentrates model and provenance complexity behind one method, per boundary discipline.

## Exact policy consumer

Shadow mode records the interpretation and makes no policy change. The opt-in active experiment has one allowed effect: an `ALTERNATIVE` referring to a validated sheet in the latest supplier message can exempt that sheet from `react()`'s clause-adopted skip. Existing must-have validation and `eco.cost()` still determine whether to adopt its whole non-price mix. Code recalculates the price through normal policy flow. No extra proposal is appended; no acceptance is vetoed.

Preferences, conditions, historical withdrawals, and inferred availability remain advisory in this first version. The kit's structured term sheets are binding; prose cannot revoke them. A model-only condition cannot remove a package, impose a buyer requirement, resurrect an old quote, change cost assumptions or bypass final/agreed handling. The current standing offer remains the acceptance authority. Applying linked conditions to newly constructed counteroffers requires a separate policy design: copying a condition into state alone is not enough.

An alternative present in a valid current term sheet is already structural evidence. Therefore a parallel deterministic comparison should remove the clause skip for all such alternatives; the LLM should not become required to rediscover availability encoded by the API. If it adds no useful semantic distinction, omit the live model consumer and retain diagnostic output only. This is an architectural comparison, not score-driven prompt tuning.

## Validation and state lifetime

- Validate the response against exactly the supplied choice catalog; reject unknown/duplicate selections and nonfinite confidence values. Confidence never grants authority.
- Resolve package and evidence within the same supplier prefix. Reject future messages, mismatched hashes and non-supplier evidence for supplier conditions.
- Limit active candidates to the latest supplier quotation; historical offers are context, not executable current packages. Supersession semantics are not guessed.
- Validate original full package with fixed terms, allowed options and must-haves. Never splice fields from two packages.
- Cache by case/supplier/prefix/prompt/model hash; retries on the same prefix are idempotent. A new reply creates a new reading, not a model-written persistent belief.
- Shared fixed deadline for both calls, bounded workers, no retry during a negotiation. Timeout returns unavailable and existing policy proceeds.

Matching references and quotations proves provenance, not entailment. A second model decision is another interpretation, not independent proof. Conflicts or ambiguity stay visible and non-authoritative.

## Verification

Fixtures must show: unchanged policy when disabled/shadow/unavailable; no state mutation on malformed or stale responses; preference cannot impose a condition; separate packages cannot combine; earlier context is present but current quote scope stays intact; duplicate input produces no duplicate call; transport failures remain baseline; a valid alternative changes only eligible candidate consideration; higher-cost or invalid alternatives never become selected simply because the model nominated them. Include identical history prefixes with and without a prior explicitly scoped condition, and adversarial withdrawal/renewal messages. Archived P08/P18 provide realistic replay but cannot estimate changed final negotiation scores.

## Alternatives and tradeoffs

Full free-form JSON extraction can express more conditions but requires wider semantic validation and more policy consumers. A persistent event ledger introduces expiry/retraction and duplicate-application bugs before those consumers exist. This bounded design accepts incomplete interpretation in exchange for a small auditable integration. It makes incompleteness explicit rather than calling it an exhaustive state.

## Synthesis decision

Pending parent cross-review. Main advantage: builds on the existing decision client and prevents invented numeric values. Main disadvantage: a two-stage categorical call cannot represent arbitrary conjunctions or dates; those must remain advisory/unrepresented until a consumer is designed.
